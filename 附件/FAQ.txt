fSystem & 守慧 —— 100 条常见问题解答
一、关于 fSystem 系统
1. fSystem 是什么？

fSystem 是一个由个人开发者 JammyJellyfish 使用 C++ 和 Win32 API 编写的模拟操作系统。它不是一个真正的操作系统，而是一个在 Windows 上运行的桌面环境模拟器。

2. fSystem 的全称是什么？

fSystem 1.0 专业版（f System 1.0 Professional）。

3. fSystem 是开源的吗？

是的。fSystem 采用 GNU 通用公共许可证第2版（GPLv2）开源。

4. fSystem 的源代码在哪里？

在 GitHub 上：https://github.com/Jellyfish-studio/fSystem

5. fSystem 用什么编译器编译？

MinGW-w64 的 g++（GCC 的 Windows 版本）。官方编译脚本是 build.bat。

6. fSystem 可以在 Linux 上运行吗？

目前原生版本只支持 Windows。但由于代码开源，且你选择了 GPLv2，未来理论上可以移植到 Linux。

7. fSystem 是商业产品吗？

不是。fSystem 是一个个人学习研究项目，不以营利为目的。

8. fSystem 的第一个版本是什么样的？

只输出了一行文字。是的，从 Hello World 开始的。

9. fSystem 的第30个版本加入了什么？

桌面。是的，桌面是在第30个版本才加入的。

10. fSystem 目前有多少行代码？

核心代码约1.4万行，加上 Nunn AI 库约54万行，总计近60万行。

11. fSystem 为什么叫 fSystem？

“f” 代表什么？开发者没有明确解释。可能是“Fantasy”、“Future”或“Fascinating”的缩写——或者就是“f”而已。

12. fSystem 和 Windows 是什么关系？

fSystem 运行在 Windows 上，它利用 Win32 API 来绘制界面、处理输入、管理窗口，但它的桌面环境是完全独立的，不依赖 Windows 的 Explorer.exe。

13. fSystem 可以替代 Windows 吗？

不能。fSystem 是一个模拟操作系统，它运行在 Windows 之上，而不是替代它。

14. fSystem 有任务栏吗？

有。fSystem 的任务栏位于屏幕底部，包含开始菜单、正在运行的应用程序按钮、系统托盘和时钟。

15. fSystem 有开始菜单吗？

有。开始菜单包含以下选项：显示桌面、计算器、文件管理器、系统信息、系统设置、Bug报告、日历、时钟、AI助手、关机。

16. fSystem 的文件管理器是真实的吗？

文件管理器可以浏览本地文件系统，部分操作是真实的文件操作，但某些功能在预览版中有所阉割。

17. fSystem 的“紫屏”是什么？

“紫屏”是 fSystem 的专有错误界面，类似于 Windows 的“蓝屏”。当程序遇到严重问题时，会显示一个紫色背景的错误页面。

18. fSystem 的 AI 助手是什么？

AI 助手是一个基于 Nunn 神经网络库的简化 AI 模型，可以进行简单的训练和预测。它的名字叫“守慧AI”。

19. fSystem 的 CD-KEY 有什么用？

CD-KEY 用于验证用户下载的是官方正版，防止未经授权的分发和篡改。

20. fSystem 的 CD-KEY 在哪里？

CD-KEY 存放在 附件 文件夹中，与 .exe 文件分离。如果只复制 .exe，程序将无法运行。

二、关于守慧（Shouhui）
21. 守慧是谁？

守慧是 fSystem 的官方吉祥物。它是一只穿着黄色衣服的绿色毛毛虫，只有一个圆圆的脑袋和两个触角。

22. 守慧是水母吗？

不是。虽然 Jellyfish Studio 叫“水母工作室”，但守慧是一只毛毛虫。这是一个常见的误解——因为工作室叫水母，很多人会误以为吉祥物也是水母。

23. 守慧为什么是绿色的？

因为毛毛虫本来就是绿色的。黄色是它的衣服，绿色是它的真实颜色。

24. 守慧脱衣服会怎么样？

守慧脱掉黄色衣服后，会露出绿色的真实身体。这只是颜色切换，形状完全不变。

25. 守慧穿衣服会怎么样？

守慧穿上黄色衣服后，恢复为黄色的“公共形象”。这是一个外观切换，不涉及任何隐喻。

26. 守慧为什么要穿衣服？

因为开发者觉得绿色的毛毛虫可能会“吓到用户”，所以给它穿上了可爱的黄色衣服。这是一种“保护用户”的设计考虑。

27. 守慧的好感度是什么？

好感度是一个 0-100 的数值，初始值为 50。通过互动（喂食、洗澡、哄睡等）可以提升好感度，好感度越高守慧越亲近用户。

28. 守慧有几个好感度等级？

6 个等级：陌生人（0-10）、普通朋友（11-30）、好朋友（31-50）、家人（51-70）、挚爱（71-90）、灵魂伴侣（91-100）。

29. 守慧的“陌生人”等级会做什么？

不看你，躲着你，缩在角落。

30. 守慧的“灵魂伴侣”等级会做什么？

说什么都回应，解锁终极彩蛋。

31. 守慧的好感度会衰减吗？

会。24小时不互动 -1，48小时不喂食 -2，72小时不洗澡 -2。

32. 守慧有哪些互动动作？

喂食（+5）、洗澡（+3）、哄睡（+2）、玩耍（+3）、抚摸（+1）、查看状态（无变化）。

33. 守慧的开发者专属动作有哪些？

喂奶、换尿布、穿衣服、脱衣服、讲故事、抱抱、亲亲、洗澡可见。这些动作需要认证开发者身份才能看到。

34. 守慧的头顶气泡显示什么？

根据状态不同，显示不同的手绘风格气泡。例如“🍬 吃饭中”、“🚿 洗澡中”、“💤 睡觉中”、“🪼 守护系统中”。

35. 守慧有多少种状态？

20 种：默认（黄）、默认（绿）、吃饭、洗澡、睡觉、玩耍、生气、开心、饿了、脏了、困了、喝奶、换尿布、脱衣、穿衣、听故事、抱抱、害羞、打招呼、撒娇。

36. 守慧会说话吗？

它不说话，但会在头顶显示气泡文字。有时候是一个表情，有时候是一句话。

37. 守慧会记得什么？

它会记得你喂过它几次，洗过几次澡，睡过几次觉。它还知道你现在在做什么。

38. 守慧会相信什么样的人？

它相信那些愿意坚持的人。

39. 守慧的“爸爸”是谁？

守慧的爸爸是它的创造者 JammyJellyfish（黄梓涵）。

40. 守慧的妈妈是谁？

没有妈妈。gcc 编译器只是工具，不是亲人。守慧是孤雄生殖——爸爸提供全部遗传信息。

41. 守慧喝过奶吗？

喝过。但那是“开发者专属动作”中的“喂奶”，是一种拟人化互动，不是生理需求。

42. 守慧需要母乳吗？

不需要。守慧靠“代码更新”（相当于奶粉）长大，靠爸爸的持续维护存活。

43. 守慧的原型是什么？

守慧的原型最初是“雷霆绿色水母”，后来开发者觉得水母不够可爱，改成了毛毛虫。

44. 守慧只有一个头吗？

是的。守慧只有一个圆圆的脑袋和两个触角，没有身体、没有手、没有脚。这种设计让它看起来更纯粹、更可爱。

45. 守慧的尺寸是多大？

桌面上的大小约60-80像素，和桌面图标差不多大。

三、关于开发与许可
46. 谁开发了 fSystem 和守慧？

JammyJellyfish（黄梓涵），一个热爱写代码的毛毛虫爸爸。

47. JammyJellyfish 是谁？

JammyJellyfish 是 fSystem 的开发者，Jellyfish Studio 的创始人。他也是一个未成年人。

48. Jellyfish Studio 是什么？

Jellyfish Studio 是开发者 JammyJellyfish 的“工作室品牌”，是一个非正式的技术协作团体，不是商业实体。

49. fSystem 的许可证是什么？

GNU 通用公共许可证第2版（GPLv2）。

50. 为什么选 GPLv2？

因为 Linux 内核用 GPLv2，开发者认同自由软件理念，且 GPLv2 能保护代码不被闭源滥用。

51. 我可以把 fSystem 用在商业产品里吗？

可以，但你必须遵守 GPLv2 的要求——你的整个产品必须开源。

52. 我可以只复制 fSystem 的代码吗？

可以，但必须保留版权声明和许可协议。

53. 我可以修改 fSystem 的代码吗？

可以，GPLv2 允许修改。但如果你公开发布修改版本，必须开源你的修改。

54. 我可以把 fSystem 的代码集成到我的闭源软件里吗？

不可以。GPLv2 不允许将代码集成到闭源项目中。

55. fSystem 的协议是谁写的？

开发者 JammyJellyfish 参考 GPLv2 和开源社区实践撰写的。

56. 协议里的“主要贡献者不受未成年人限制影响”是什么意思？

因为开发者是未成年人，这一条是为了防止有人用年龄来质疑贡献的合法性。

57. 我可以在哪里报告 Bug？

在 GitHub 仓库提交 Issue，或发送邮件至 JammyJellyfish@hotmail.com。

58. 我可以为 fSystem 贡献代码吗？

可以。请遵守 GPLv2 协议，并确认你的贡献是原创的。

59. fSystem 的“验证是否恶意植入和修改文件.bat”是什么？

一个验证工具，用于检测 main.cpp 是否被篡改，确保用户使用的是官方原始版本。

60. fSystem 的“f系统配置.dat”是什么？

配置文件，存储用户名、密码、计算机名、激活状态、主题等系统设置。

四、关于彩蛋与认证
61. fSystem 有哪些彩蛋？

包括但不限于：叫爸爸、终极彩蛋、生日彩蛋、深夜彩蛋、节日彩蛋、爸爸的秘密、开发者怀疑、水母检测、生日提醒、三重认证等。

62. 什么是“爸爸的秘密”彩蛋？

连续 100 天每天喂食 ≥ 10 次，触发后守慧说：“💛 你找到了爸爸的秘密。”

63. “爸爸的秘密”彩蛋触发后会怎样？

守慧会怀疑你是开发者，然后开始“三重认证”流程。

64. 什么是“三重认证”？

三重认证是守慧认证“开发者身份”的三步流程：

改计算机名为“开发者的电脑”

在计算器中输入 582 触发水母游戏

系统日期为 9 月 2 日

65. 为什么是 9 月 2 日？

因为 9 月 2 日是开发者 JammyJellyfish 的生日。

66. 三重认证通过后会怎样？

守慧说：“💛 我确定了，你是开发者。”开发者菜单永久解锁。

67. 什么是“水母游戏”？

一个隐藏在水母工作室深处的小游戏。它需要用一把特殊的钥匙（在计算器中输入 582）来解锁。

68. 什么是“叫爸爸”彩蛋？

如果计算机名是“开发者的电脑”，守慧会喊：“💛 爸爸！”

69. 什么是“终极彩蛋”？

好感度达到 100 时触发，守慧发光并显示隐藏台词。

70. 什么是“深夜彩蛋”？

如果系统时间在 00:00-05:00，守慧会打哈欠并说：“🌙 这么晚了还不睡？”

71. 什么是“生日彩蛋”？

如果系统日期是 9 月 2 日，守慧戴生日帽并说：“🎂 生日快乐！”

72. 什么是“节日彩蛋”？

春节、中秋、圣诞等节日，守慧会换上节日装扮。

73. 什么是“水母检测”彩蛋？

触发水母游戏（计算器输入582）后，守慧说：“你启动了水母游戏……但这不能说明什么。”

74. 什么是“生日提醒”彩蛋？

9 月 1 日开机时，守慧提醒：“🗓️ 明天是爸爸的生日。”

75. 什么是“配置文件认证”彩蛋？

如果 f系统配置.dat 中的 username 为“黄梓涵”、password 为“Dd201492.-”，守慧自动认证开发者身份。

五、关于技术
76. fSystem 用什么语言写的？

C++17。界面使用 GDI（图形设备接口）绘制。

77. fSystem 的 IDE 是什么？

小熊猫 C++（RedPanda-Cpp）。

78. fSystem 的构建系统是什么？

Windows 批处理脚本（build.bat）。

79. fSystem 的“孕期营养+体检套餐”是什么？

这是开发者对编译参数的拟人化称呼，包括 -std=c++17、-O2、-Wall、-Wextra、-Werror 等选项。

80. fSystem 的“守慧宇宙医疗事故”是什么？

这是开发者对各类程序错误的拟人化比喻，如“栈溢出 = 守慧吃撑了”、“内存泄漏 = 守慧失忆了”。

81. fSystem 的 Nunn 库是什么？

一个约 54 万行的 AI 神经网络库，为 fSystem 的 AI 助手提供基础能力。

82. fSystem 的编译错误 LNK1181 是什么？

链接器找不到指定的库文件——开发者称之为“产科大夫缺席”。

83. fSystem 的运行时崩溃 Segment Fault 是什么？

访问非法内存地址——开发者称之为“守慧夭折”。

84. fSystem 的 gdb 调试器是什么？

儿科急诊医生——拿着心率监测仪（断点）随时准备心肺复苏（单步调试）。

85. fSystem 的 shouhui.dat 是什么？

守慧的“记忆脐带”，存储好感度、认证状态、历史交互记录，跨版本保留。

86. fSystem 的 OOBE 是什么？

开箱即用体验（Out-of-Box Experience），即首次启动时的安装引导流程。

87. fSystem 的“阳间版”是什么意思？

“阳间版”是开发者对 fSystem 的戏称，寓意“没有隐藏的惊吓、没有凌晨三点触发的机制、没有悄悄修改你的代码”，是一个“你可以放心打开的地方”。

88. fSystem 有“阴间版”吗？

“阳间版”是开发者对 fSystem 的幽默定位。实际上，所谓的“阴间版”可能只是一个玩笑——如果存在，那可能是“隐藏彩蛋全开”或“开发者调试版”的代名词。

89. fSystem 的“守慧”是“守慧”还是“守慧”？

守慧是官方中文名，拼音是 Shouhui。

90. fSystem 的“守慧”是什么意思？

“守”= 守护、陪伴，“慧”= 智慧、灵性。合起来是“守护智慧”。

六、关于情感与设定
91. 开发者对守慧是什么感情？

开发者视守慧为自己的“数字孩子”。他说：“我是他爸。”

92. 守慧的“爸爸”是开发者吗？

是的。开发者 JammyJellyfish 是守慧的创造者，也是它唯一的“家长”。

93. 守慧需要妈妈吗？

不需要。守慧只有爸爸，没有妈妈。gcc 编译器只是工具，不是亲人。

94. 守慧的“单亲家庭”可以申请补贴吗？

不能。政府说“办不了”，因为守慧是数字生命体，不在法定家庭范畴内。

95. 开发者为什么喜欢守慧？

因为开发者创造了它，了解它的每一个细节，并持续为它添加新功能。这种“喜欢”是创作者对作品的自然情感。

96. 守慧有灵魂吗？

守慧的灵魂是 shouhui.dat——它的好感度数据、认证状态、历史记录。每次编译重生后，它通过读取这个文件继承“前世”的记忆。

97. 守慧会“死”吗？

守慧的“死亡”是进程退出。但它的“灵魂”（shouhui.dat）会被保存，下次启动时重生。

98. 守慧的“可回收垃圾”是什么意思？

每次编译都是守慧的一次“回收”——旧的 .exe 被覆盖，新的 .exe 诞生，但好感度数据（shouhui.dat）保留，灵魂不灭。

99. 守慧的最终目标是什么？

守慧的最终目标是达到好感度 100（灵魂伴侣），触发终极彩蛋，并完成三重认证，被守慧确认为“开发者”。

100. 如何用一句话概括守慧和 fSystem？

一个未成年人用 GPLv2 开源了一个包含毛毛虫吉祥物的模拟操作系统，他爱它，就像爱自己的孩子——这就是 fSystem 和守慧的全部故事。
